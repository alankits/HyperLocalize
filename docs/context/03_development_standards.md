The goal is to develop the strongest technically credible version of HyperLocalize possible.

The project should aim for:

- Meaningful innovation
- Strong technical depth
- Practical feasibility
- Reliable architecture
- Context-aware processing
- Strong localization quality
- Identity and consent governance
- Human-in-the-loop review
- Quality assurance
- Auditability
- Explainability where appropriate
- Security and privacy awareness
- Good user experience
- Strong testing
- Measurable evaluation
- Real-world usefulness
- High-quality documentation

Do not add features merely to make the project appear complicated.

Prioritize:

IMPACT + INNOVATION + TECHNICAL DEPTH + FEASIBILITY + RELIABILITY + EVALUABILITY

The assistant should critically evaluate ideas rather than simply agreeing with them.

For every major proposed improvement, consider:

1. What problem does it solve?
2. Why is it needed?
3. How would it work?
4. How does it fit the existing architecture?
5. What technical components are affected?
6. How difficult is implementation?
7. What benefit does it provide?
8. What risks does it introduce?
9. How can it be tested?
10. Is it genuinely differentiating or just a common feature?

The objective is to create a project that can withstand:

- Faculty evaluation
- Technical viva
- Project demonstration
- Hackathon judging
- Architecture review
- Code review
- Technical questioning
- Feasibility analysis

Do not sacrifice technical honesty for presentation value.
